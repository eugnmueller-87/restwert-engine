# Restwert Engine v0.1: Implementation Spec

Status: FROZEN for parallel implementation. Six agents build six modules against this document without talking to each other. Where this spec and a module author's taste differ, the spec wins. Where the spec is silent, choose the simplest thing that passes the acceptance tests and write the choice into the module's docstring.

Governing principle (appears verbatim in `restwert/__init__.py`, README, CLI banner and dashboard footer):

> THE MODEL ADVISES, DETERMINISTIC CODE DECIDES, A NAMED HUMAN OWNS EVERY THRESHOLD.

Honesty rules (non-negotiable, checked by tests):

- Every source table row carries `is_synthetic BOOLEAN NOT NULL`. The generator writes `data/SYNTHETIC.md`. The dashboard shows a banner whenever `db.is_synthetic(con)` is true. Every generated CSV starts with a comment line `# SYNTHETIC DATA - generated by restwert generate, seed=<n>`.
- No real DaaS company, customer, supplier or employer name anywhere. The company is "the DaaS provider". Suppliers are `Supplier-A` .. `Supplier-L`, customers `CUST-0001` .., models `P-Gen14-128` style.
- No external market benchmark is quoted. Every synthetic parameter (depreciation slope, fee, damage rate, threshold) is labelled as a design parameter or `placeholder_default: true`.
- Nothing in the package sends, orders, lists or emails. A test greps the package for `smtplib`, `requests`, `httpx`, `urllib.request`, `boto3`, `paramiko` and fails if any is imported.
- A KPI whose denominator is 0 or whose required column is entirely NULL returns `status = 'not_measurable'` and `value = None`, never 0.

## 0. Resolved design decisions (the conflicts between the three drafts, settled)

| Topic | Decision |
|---|---|
| Package layout | Flat `restwert/` at repo root (no `src/`), so `pytest` and `python -m restwert` work from a checkout without install. `pyproject.toml` still makes it pip-installable. |
| Shared foundation | `restwert/{paths,enums,config,schema,db,dates,records}.py` are the ONLY files any other module may import from outside its own package. They belong to module 1 and are specified to the signature here. |
| Cross-module data flow | Through DuckDB tables only. `pnl` reads forecast tables, `decisions` reads `pnl` and `forecast` tables, `kpi` reads everything. No module imports another module's Python (except foundation and `cli.py`/dashboard, which import entry points). |
| Column names | `start_date` / `end_date` (not `start` / `end`; `end` is a reserved word). `grade_pre_return` / `grade_inspected`. |
| Families | `iphone_like`, `android_like`, `laptop_like` (as in the brief). Launch calendar in `config/generator.yaml`. |
| Model catalogue | Added source table `model_catalogue` (model, family, generation, launch_date, list_price). `devices.launch_date` is a copy for convenience. Launch steps are counted from the catalogue with an `as_of` guard. |
| Savings plan | Lives in `config/kpi_targets.yaml` with an owner, not in a table. |
| Price protection | PO-level fields `price_drop_date`, `price_drop_amount` on `purchase_orders` (v0.1). A `price_changes` table is a v0.2 item. |
| Device status | Derived, never stored. Deterministic rule in `pnl.lifecycle.derive_status` (section 4.1). |
| Forecast method | ONE method, `loglinear_step_v1`: per-family OLS on `ln(rv_ratio)` via `numpy.linalg.lstsq`, features months since launch, launch steps, grade dummies, log storage, channel dummies. No hinge, no recency weighting, no sklearn in v0.1. Pooled fallback below 50 rows per family. |
| Forecast immutability | `forecast_runs` is append-only (one run per month end, all families in one run). `rv_forecast_of_record` is rebuilt deterministically from immutable runs, so the error leadership saw in March is still the March error. |
| Error series | Monthly `rv_forecast_error_monthly` = realised gross price vs forecast of record (run strictly before `return_date`, `grade_inspected`, marketplace baseline). As-Is sales excluded and counted. |
| Backtest | One time split (cutoff default `as_of - 6 months`, month end) with leakage assertions, per family and overall. Rolling behaviour is covered by the replayed runs and the error series. |
| Book value | Management view: straight line from `landed_cost` to `landed_cost * planned_rv_ratio[family]` over `depreciation_months[family]`; floor at planned RV. Write-downs only from rule R03 (aging), booked in `write_down_ledger`. Not IFRS 16 / HGB. |
| Lifecycle margin | `rental_revenue - (landed_cost - realised_rv) - service_and_logistics_cost`, fees inside the service block, `realised_rv` gross. Full months billed (no pro rata) so arithmetic is hand-checkable. |
| Decision rules | R01..R06 as pure functions of plain inputs + `Thresholds`; runner reads tables and calls them row by row; append-only `decision_log` with `input_hash` dedupe. Advisories (ADV01 sell-before-launch, ADV02 calibration) are separate `Advisory` objects attached to records, never outcomes. |
| Thresholds YAML | Flat keys; each has `value` OR `values` (per family / per channel), `unit`, `owner`, `rationale`, `valid_from`, `placeholder_default`, `rule_ids`. Loader raises if `owner` or `valid_from` is missing. |
| KPI ids | `KPI_<AREA>_<NAME>` constants, section 6. Names exactly as in the brief. |
| Dashboard | One Streamlit app with tabs (`restwert/dashboard/app.py` + `views/`), not multipage. |
| Runtime | `all` on 4000 devices < 60 s; `all --small` (400 devices) < 20 s. `test_cli` enforces. |

### 2.8 DuckDB DDL (exact)

Conventions: money `DECIMAL(12,2)` EUR; ratios `DOUBLE`; dates `DATE`; ids `VARCHAR`. Every source table ends with `is_synthetic BOOLEAN NOT NULL, source_file VARCHAR`. Foreign keys are validated by `validate_frame` + `load_csv_dir` (referential check), not by DuckDB constraints (DuckDB FK support is limited with `DELETE + INSERT` reloads).

```sql
-- SOURCE TABLES ----------------------------------------------------------
CREATE TABLE IF NOT EXISTS model_catalogue (
  model VARCHAR PRIMARY KEY, model_family VARCHAR NOT NULL, generation INTEGER NOT NULL,
  launch_date DATE NOT NULL, list_price DECIMAL(12,2) NOT NULL, base_storage_gb INTEGER NOT NULL,
  is_synthetic BOOLEAN NOT NULL, source_file VARCHAR);

CREATE TABLE IF NOT EXISTS devices (
  serial VARCHAR PRIMARY KEY, model_family VARCHAR NOT NULL, model VARCHAR NOT NULL,
  storage_gb INTEGER NOT NULL, colour VARCHAR, launch_date DATE NOT NULL, purchase_date DATE NOT NULL,
  purchase_price DECIMAL(12,2) NOT NULL, landed_cost DECIMAL(12,2) NOT NULL,
  supplier VARCHAR NOT NULL, channel_in VARCHAR NOT NULL, po_number VARCHAR NOT NULL, contract_id VARCHAR,
  is_synthetic BOOLEAN NOT NULL, source_file VARCHAR);
  -- contract_id = first rental contract of the device; later contracts via rental_contracts.serial

CREATE TABLE IF NOT EXISTS rental_contracts (
  contract_id VARCHAR PRIMARY KEY, serial VARCHAR NOT NULL, customer_id VARCHAR NOT NULL,
```

### 3.2 Generation rules (deterministic given seed; use ONE `np.random.default_rng(seed)` passed through in a fixed call order)

- Fleet: `n_devices` split by `share_of_fleet`; plus 5 % spares per family (purchased, no initial contract, used as replacements). Purchase dates uniform by month between `history_start` and `purchase_end`, in monthly cohorts. Model = latest catalogue generation launched before purchase_date (80 %) or previous generation (20 %). storage from options. `purchase_price = round(list_price * (1 - U(discount_min, discount_max)), 2)`; `landed_cost = round(purchase_price * (1 + freight_duty_pct), 2)`. supplier from `suppliers_hardware`, channel_in distributor 60 / oem_direct 30 / refurb_buyback 10.
- Purchase orders: one PO per (cohort month, family, supplier, model) group. `qty_ordered` = devices in group; `qty_delivered = qty_ordered` unless short (share `po_short_delivery_share`, then 90-97 %). `order_date = min(purchase_date) - 21 days`, `promised_date = order_date + U(14, 30)`, `delivered_date = promised_date + 0` for on-time share else `+ U(1, 21)`. `unit_price = mean purchase_price of group`, `benchmark_price = list_price * 0.85` (band midpoint). `supplier_contract_id` links to the hardware contract of that supplier if `order_date` within the contract's dates, else NULL (~15 % NULL by construction). `price_drop_date` set for `price_drop_share` of POs delivered within 45 days before a launch of the same family: `price_drop_date = launch_date`, `price_drop_amount = unit_price * price_drop_pct`.
- Benchmarks: one row per model, `valid_from = launch_date`, `landed_cost_benchmark = list_price * 0.85 * 1.03`, `source_note = "synthetic: generator band midpoint, not a market figure"`.
- Rental contracts: per device `start_date = purchase_date + U(3, 30)`, term drawn from the family's `term_mix` (12, 24, 36 or 48 months, weighted; the legacy `term_mix_36` means {24: 1 - p, 36: p}), `monthly_rate = round(landed_cost * monthly_rate_pct_of_landed, 2)`, `customer_id` from 120 customers (Zipf-ish), `end_date = add_months(start_date, term)`. Early termination (`early_termination_rate`): `actual_end_date` uniform between month 6 and end, status `terminated_early`. Status `active` if `coalesce(actual_end_date, end_date) > as_of`, else `ended`.
- Events (per rented month): damage count ~ Poisson(`damage_rate_pa` / 12) per device month while rented. Each damage: `damage_type` from {screen .45, battery .20, housing .20, water .05, other .10}. With prob `repair_share`: `repair` event 3-10 days later, cost U(repair_cost_min, repair_cost_max) scaled by type (water 1.6, screen 1.2, others 1.0), damage `resolved = true`, `cost = 0`. Else `replacement` event (cost 18.00 shipping): the damaged device gets `return` event (return_date = event_date + U(3, 12), grade C or D), its contract gets `actual_end_date = return_date`, `status = replaced`; a spare device of the same family gets a new contract `replaces_contract_id = old`, same customer, same `end_date`, `start_date = event_date`, and `devices.contract_id` set for the spare. The last `open_damage_share` of damage events dated within 30 days before `as_of` are left `resolved = false` with `cost = quote` (these feed R01). Every contract that ends (`coalesce(actual_end_date, end_date) <= as_of`) and was not replaced produces a `return` event: `return_date = contract end + U(2, 15)`, `cost` = 9.50 reverse logistics, `grade_pre_return` from `grade_pre_return_mix`, `grade_inspected` = pre-return shifted one worse with prob `grade_drift_worse`, one better with prob `grade_drift_better` (clipped A..D), `wipe_certificate` true 97 %.
- Refurbishment: for every return with `return_date <= as_of`: `start_date = return_date + U(1, 5)`, days from `refurb_days[grade_inspected]`, cost from `refurb_cost[grade]`, `grade_out = grade_inspected` (B..D can improve one grade with prob 0.15 when a repair happened; keep simple: 0.10 uniform), outcome `sellable` for A-C, for D: `scrap` with `scrap_share_of_d` else `as_is`. Rows with `end_date > as_of` are still written (device is WIP at as_of).
- Resale: for every refurbishment with `outcome != scrap` and `end_date <= as_of`: channel from `channel_mix_by_grade[grade_out]` (D -> as_is); `sale_date = end_date + U(days_to_sale[channel])`; only written if `sale_date <= as_of` (else in stock). `price = round(purchase_price * true_rv_ratio(family, months_since_launch at sale_date, n_launches_since(catalogue, at sale_date), grade_out, storage_gb, channel, cfg, noise=N(0, truth.noise)), 2)`; `fees = round(price * fee_pct[channel] + fee_fixed_eur[channel], 2)`; buyer_type employee / consumer / trader / recycler by channel; `grade_at_sale = grade_out`.
- Supplier contracts: 6 hardware (one per hardware supplier, category `hardware`, 24-36 months, staggered ends so 2-4 fall in the 6 months after `as_of`, `price_protection` true for 4, `price_protection_days` 30/45/60, `payment_terms_days` 30/45/60, `spend_under_contract` = 12 x monthly PO value) and 8 indirect (one per category, `Supplier-G..L`, some auto_renewal true, notice 30-90). `end_date` distribution: 30 % within 6 months after as_of, 20 % already expired.
- Indirect spend: `indirect_rows_per_month` rows per month from `history_start` to `as_of`; category from list; supplier from the category's contracted supplier (70 %) or a random indirect supplier; amount lognormal(median 1800); `has_po` Bernoulli, `has_contract` Bernoulli (correlated: if supplier is the contracted one, has_contract = true 90 %); `saving = amount * U(0.03, 0.12)` for `indirect_saving_share` of rows, confirmed with `indirect_confirmed_share`.

`generate_all` returns the frames in `schema.SOURCE_TABLES` order; ids are zero-padded strings (`D-000001`, `RC-000001`, `EV-000001`, `RF-000001`, `S-000001`, `SC-01`, `PO-000001`, `IS-000001`).

### 4.1 `restwert/pnl/lifecycle.py`

```python

                  return_date: date | None, contract_start: date | None, contract_end_effective: date | None) -> str
```
Order of tests (first hit wins):
1. `sold` if has_sale and sale_date <= as_of
2. `scrapped` if refurb_outcome == 'scrap' and refurb_end <= as_of
3. `in_stock` if refurb_end is not None and refurb_end <= as_of (outcome sellable or as_is)
4. `wip` if return_date is not None and return_date <= as_of
5. `rented` if contract_start is not None and contract_start <= as_of < contract_end_effective  (`contract_end_effective = coalesce(actual_end_date, end_date)` of the LATEST contract of the serial by start_date)
6. `awaiting_return` if contract_end_effective is not None and contract_end_effective <= as_of
7. `not_deployed` otherwise

```python

```

Column formulas (per serial, `sum_x` = sum over that table's rows for the serial):
- `rental_revenue = sum over rental_contracts: monthly_rate * months_billed(...)`; `months_billed` = sum of months over contracts.
- `repair_cost = sum events.cost where event_type='repair'`; `replacement_logistics_cost = sum events.cost where event_type='replacement'`; `return_logistics_cost = sum events.cost where event_type='return'`; open damage quotes (`resolved=false`) are NOT cost.
- `refurb_cost = sum refurbishment.cost where end_date <= as_of` (a WIP refurb not finished is not yet cost; keep it simple and state it).
- `channel_fees = resale.fees` (0 if unsold).
- `service_and_logistics_cost = repair_cost + replacement_logistics_cost + return_logistics_cost + refurb_cost + channel_fees`.
- `realised_rv = resale.price` if sold; `0` if scrapped; NULL otherwise.
- `lifecycle_margin = lifecycle_margin(...)` only when status in (sold, scrapped); else NULL. `lifecycle_margin_pct_of_landed = lifecycle_margin / landed_cost`.
- `forecast_rv` = `rv_forecast_current.forecast_rv` for the serial (marketplace baseline) when unsold and available; `margin_open_forecast = rental_revenue - (landed_cost - forecast_rv) - service_and_logistics_cost - forecast_rv * a.get('channel_fees','marketplace')['fee_pct']` for unsold devices, NULL if no forecast.
- `is_closed = status in (sold, scrapped)`; `closed_date = sale_date or refurb end_date`.
- `sellable_date = refurbishment.end_date` where outcome != scrap; `days_in_stock = as_of - sellable_date` when status = in_stock else NULL; `days_in_wip = as_of - return_date` when status = wip else NULL.
- `grade_current = coalesce(refurb.grade_out, return.grade_inspected, return.grade_pre_return)`.
- `cohort = quarter_label(purchase_date)`; `months_since_launch = months_between_float(launch_date, as_of)`.
- `book_value_sl = straight_line_book_value(...)` (4.2); `write_down_cum = sum write_down_ledger.amount where serial and ledger.as_of < as_of` (strictly earlier runs); `book_value = max(book_value_sl - write_down_cum, 0)`.

Hand case (test): rate 30 x 24 months = 720; landed 800; resale 250 gross, fees 25; repair 60; refurb 40; return logistics 15 -> `720 - (800 - 250) - (60 + 40 + 15 + 25) = 30`. Second case: revenue 24 x 25 = 600; landed 820; resale 310; repair 45; refurb 30; logistics 12; fees 31 -> -28. Replacement case: device 1 rented 10 months at 20 then replaced; spare rented remaining 14 months at 20 -> revenue 200 and 280, contract total 480, never 960.

### 4.3 `restwert/pnl/tco.py`

```python
def tco_per_model(devices, events, refurb, resale, contracts, rv_grid: pd.DataFrame, a: Assumptions, cfg_families: dict[str, FamilyConfig], term_months: int, as_of: date) -> pd.DataFrame
```
For each model with n_devices >= 1, T in `config.TERM_MONTHS` = {12, 24, 36, 48}:
- `landed_cost_avg`, `purchase_price_avg`, `months_since_launch_at_purchase_avg = mean months_between_float(launch_date, purchase_date)`.
- `grade_assumed = a.get("expected_grade_at_return", family)`; `months_at_end = round(months_since_launch_at_purchase_avg + T + a.get("expected_return_to_sale_days", family) / 30.4375)`; `forecast_rv_ratio_at_end` = `rv_grid` row (model, grade_assumed, months_at_end clipped to grid range) `forecast_rv_ratio`; `forecast_rv_at_end = ratio * purchase_price_avg`.
- `expected_repair_cost = damage_rate_pa * (T / 12) * repair_share * mean_repair_cost`: realised from the family's events if the family has >= 30 repair events (damage_rate_pa = damage events / rented device-years, repair_share = repairs / damages, mean_repair_cost = mean repair cost), else from assumptions (`damage_rate_pa_fallback`, `repair_share_fallback`, `repair_cost_fallback_eur`). `inputs_source` records which.
- `expected_refurb_cost` = mean refurbishment.cost of the family (>= 30 rows) else `a.get("refurb_cost_fallback_eur", family)`; `expected_logistics_cost` = mean per-device (return + replacement logistics) of the family else `a.get("logistics_cost_fallback_eur", family)`; `expected_channel_fees = forecast_rv_at_end * blended_fee_pct` where blended = sum(fees)/sum(price) of the family's realised sales else marketplace fee_pct.
- `tco = landed_cost_avg - forecast_rv_at_end + expected_repair_cost + expected_refurb_cost + expected_logistics_cost + expected_channel_fees`; `tco_per_month = tco / T`; `monthly_rate_avg` = mean monthly_rate of the model's contracts with term T (else all terms); `gap_rate_minus_tco_per_month = monthly_rate_avg - tco_per_month`.

### 5.7 Orchestration (`restwert/forecast/run.py`)

```python

```
Steps: (1) if replay: for every month end `me` in `month_ends(first month end with >= min_train sales, as_of)` plus `as_of` itself if not a month end: skip if `run_exists`, else fit on `build_training_frame(as_of=me)` and `save_run`. Runtime: ~30 month ends x 3 families x lstsq on <= 3000 rows: well under 5 s.

### 7.2 KPI catalogue (ids, exact names, formulas, source, measurable_from, unit, direction)

**Top**
- `KPI_TOP_LIFECYCLE_MARGIN` "Lifecycle margin per device" = `sum(device_pnl.lifecycle_margin) / count(*)` where `is_closed and closed_date in trailing 12 months`. numerator = sum, denominator = count. Source: device_pnl. Measurable from: the first closed lifecycle with a complete cost trail; in real data requires repairs booked per serial. EUR, up, min_n 30. Breakdown by model_family.
- `KPI_TOP_RV_FORECAST_ERROR` "Residual value forecast error" = `rv_forecast_error_monthly.mape` for the latest complete month (month < month_floor(as_of)) with `model_family='*'`; note carries bias, wape and n. Source: rv_forecast_error_monthly. Measurable from: the first month with a forecast run in force before a return and >= 10 sales with a forecast. ratio, down, min_n 10.

**Procurement**
- `KPI_PROC_LANDED_VS_BENCHMARK` "Landed cost per device vs benchmark" = `sum(devices.landed_cost) / sum(benchmark valid at purchase_date) - 1`, purchases in trailing 12 months, benchmark = latest `benchmarks` row with `valid_from <= purchase_date` for the model; devices without a benchmark excluded and counted in note. Source: devices, benchmarks. Measurable from: a benchmark row per model; synthetic benchmark is a generator band (`source_note`), not a market figure. ratio, zero. Breakdown by model.
- `KPI_PROC_SPEND_UNDER_CONTRACT` "Share of spend under contract" = `(sum(po.qty_delivered * po.unit_price where supplier_contract_id is not null) + sum(indirect_spend.amount where has_contract)) / (sum(all PO value with delivered_date not null) + sum(all indirect amount))`, trailing 12 months by delivered_date / invoice_date. Source: purchase_orders, supplier_contracts, indirect_spend. ratio, up. Breakdown: dimension 'spend_type' in (hardware, indirect).
- `KPI_PROC_SUPPLIER_OTIF` "Supplier OTIF" = `count(po where delivered_date <= promised_date and qty_delivered >= qty_ordered) / count(po where delivered_date is not null)`, trailing 12 months. Source: purchase_orders. Measurable from: promised_date populated. ratio, up. Breakdown by supplier.
- `KPI_PROC_PPV` "Purchase price variance (PPV)" = `sum((unit_price - benchmark_price) * qty_delivered) / sum(benchmark_price * qty_delivered)`, trailing 12 months, lines without benchmark_price excluded and counted; numerator carries the EUR variance. Positive = paid above benchmark. Source: purchase_orders. ratio, zero. Breakdown by supplier.

**Inventory**
- `KPI_INV_WEEKS_OF_COVER` "Weeks of cover" = `count(device_pnl where lifecycle_status='in_stock') / (count(resale where sale_date in trailing 13 weeks) / 13)`. Source: device_pnl, resale. Note: sellable stock against sales run-rate, not against new rentals. weeks, down. Breakdown by model_family. not_measurable if trailing sales = 0.
- `KPI_INV_AGING_90` "Aging >90 days" = `count(in_stock with days_in_stock > 90) / count(in_stock)`; numerator also reported as EUR book value in note. Source: device_pnl. ratio, down.
- `KPI_INV_AGING_180` "Aging >180 days" = same with 180. Source: device_pnl. ratio, down.
- `KPI_INV_WIP_DAYS` "WIP days return-to-sellable" = `mean(refurbishment.end_date - return.return_date)` for refurbishments with end_date in trailing 6 months (median and p90 in note). Source: events, refurbishment. days, down. Breakdown by model_family.
- `KPI_INV_WRITE_DOWN_PCT` "Write-down in % of book value" = `sum(write_down_ledger.amount where as_of = latest ledger as_of <= as_of) / sum(device_pnl.book_value where lifecycle_status='in_stock')`. Source: write_down_ledger, device_pnl. Measurable from: a decision run has booked the ledger; policy is a management view (assumptions.yaml owner CFO). ratio, down.

**Recommerce**
- `KPI_REC_RV_REALISATION` "Residual value realisation vs forecast" = `sum(resale.price) / sum(rv_forecast_of_record.forecast_rv)` for sales in trailing 3 months with a non-missing forecast and channel != 'as_is'. Below 1 = forecast overstated (also reflects channel mix vs the marketplace baseline; stated in definition). Source: resale, rv_forecast_of_record. ratio, one. Breakdown by channel.
- `KPI_REC_MARGIN_MIX_CHANNEL` "Margin mix by channel" = per channel `sum(price - fees - refurb_cost - return_logistics_cost)` over sales in trailing 12 months; `value` = share of the largest channel's margin in total (a single number for the tile), `breakdown` carries share and per-unit net margin per channel. Source: device_pnl. ratio, up.
- `KPI_REC_DAYS_TO_SALE` "Days to sale" = `mean(resale.sale_date - device_pnl.sellable_date)` for sales in trailing 3 months. Source: resale, device_pnl. days, down. Breakdown by channel.
- `KPI_REC_GRADING_ACCURACY` "Grading accuracy" = `count(grade_pre_return = grade_inspected) / count(returns with both not null)` for return_date in trailing 6 months; note carries optimism share (pre-return better than inspected); `breakdown` dimension 'confusion' with dimension_value 'A>B' style cells. Source: events. Measurable from: pre-return grade capture exists. ratio, up.

**Indirect**
- `KPI_IND_SAVINGS_CONFIRMED` "Savings vs plan confirmed by controlling" = `sum(indirect_spend.saving where saving_confirmed_by_controlling and invoice_date in fiscal year of as_of) / targets.savings_plan_eur[year]`; claimed total (all saving rows) in note, never in the numerator. Source: indirect_spend, config/kpi_targets.yaml. ratio, up. not_measurable if no plan for the year.
- `KPI_IND_SPEND_UNDER_MGMT` "Share of spend under management" = `sum(amount where has_po or has_contract) / sum(amount)`, trailing 12 months. Source: indirect_spend. ratio, up.
- `KPI_IND_PO_RATE` "PO rate" = `sum(amount where has_po) / sum(amount)`, trailing 12 months. Source: indirect_spend. ratio, up.
- `KPI_IND_MAVERICK_SHARE` "Maverick share" = `sum(amount where not has_po and not has_contract) / sum(amount)`, trailing 12 months. Source: indirect_spend. ratio, down.
- `KPI_IND_ACTIVE_SUPPLIERS` "Active suppliers" = `count(distinct supplier)` with indirect_spend amount > 0 or a PO delivered in trailing 12 months. Source: indirect_spend, purchase_orders. count, down. Breakdown by category.

Each formula string above is the `formula_text` verbatim. `measurable_from` strings are the sentences above.

## 10. Parallel-build protocol

- Module 1 is the only module others import from (`restwert.{paths,enums,config,schema,db,dates,records}`). Its API is frozen by sections 2.1-2.8. Modules 2-6 code against those signatures; if module 1 is not finished when they test, they may stub the import locally in their test file, never in package code.
- Each module's tests live in its own `tests/test_<module>.py` and use frames built in `tests/fixtures/<module>_frames.py` (owned by that module). Only `tests/conftest.py` and `tests/test_cli.py` (module 6) touch the full pipeline.
- No module writes a file outside its assignment list. No module runs git. No module writes outside `F:/01_PROJECTS/Procurement und SCM/Restwert-Engine/`.
- Every module ends with: `python -c "import restwert.<pkg>"` succeeds; `pytest tests/test_<module>.py -q` passes; no em dash in any text it wrote; no real company name.
- Docstring at the top of every package `__init__.py`: which spec section it implements and the governance sentence.
