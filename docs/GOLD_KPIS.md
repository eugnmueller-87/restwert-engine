# Gold KPI catalogue (v0.2 cycle pages)

GENERATED by `restwert.gold.catalogue.write_gold_catalogue` from `restwert/gold/kpis.py`. Do not edit by hand; change the KPI definition in code and regenerate with `python -m restwert kpis --catalogue`.

> THE MODEL ADVISES, DETERMINISTIC CODE DECIDES, A NAMED HUMAN OWNS EVERY THRESHOLD.

These KPIs read the silver ledger, the timeline, the reconciliation and the gold tables of the data lake and write `gold.kpi_values` and `gold.kpi_breakdown`. The v0.1 registry (20 KPIs, five areas, `docs/KPI_CATALOGUE.md`) is frozen and untouched. A KPI whose denominator is 0 or whose table or column is missing is reported as `not_measurable` with `value = None` and a note that says why, never as 0; a KPI whose observation count is below its `min_n` (`config/kpi_targets.yaml`, owned) keeps the value for reference but is flagged `not_measurable` and the dashboard tile reads n/a with the reason. On synthetic data every number describes the design parameters in `config/lake.yaml` and `data/lake/SYNTHETIC.md`, not a market.

## 0 Data

### Share of serials with a complete timestamp chain

- **id:** `KPI_DATA_CHAIN_COMPLETE`
- **page:** 0 Data
- **owner:** Data owner (name)
- **definition:** Serials whose timestamp chain (ordered, received, staged, shipped, returned, wiped, graded, sellable, sold, credited) has every step expected for their lifecycle status, in order, over all serials in silver.serial_timeline.
- **formula:** `count(serial_timeline where chain_complete) / count(serial_timeline)`
- **source tables:** `silver.serial_timeline`
- **unit:** ratio
- **direction:** up (higher is better)
- **min_n:** 30 (config/kpi_targets.yaml, owner CFO (name); below this the value is stored but flagged not_measurable)

### Share of landing rows that could not be resolved

- **id:** `KPI_DATA_UNRESOLVED_SHARE`
- **page:** 0 Data
- **owner:** Data owner (name)
- **definition:** Rows of every ingested landing file that could not be typed or key-resolved (bronze.unresolved with reason codes other than duplicate_conflict) over all rows read, as recorded in bronze.deliveries.n_unresolved. Conflicting duplicates are counted under duplicates_conflict, not here; the breakdown lists them separately for reading. A source row that is re-delivered under a new file is recorded once per delivery.
- **formula:** `sum(deliveries.n_unresolved) / sum(deliveries.rows_read)`
- **source tables:** `bronze.deliveries`, `bronze.unresolved`
- **unit:** ratio
- **direction:** down (lower is better)
- **min_n:** 1 (config/kpi_targets.yaml, owner CFO (name); below this the value is stored but flagged not_measurable)

### Share of serials reconciled to device_pnl to the cent

- **id:** `KPI_DATA_RECONCILED`
- **page:** 0 Data
- **owner:** Data owner (name)
- **definition:** Serials whose every silver.reconciliation row (ledger value vs v0.1 device_pnl value per field) is ok, over all serials with a reconciliation row. The pipeline refuses to finish on a failure, so anything below one is a finding.
- **formula:** `count(distinct serial where every reconciliation row ok) / count(distinct serial)`
- **source tables:** `silver.reconciliation`
- **unit:** ratio
- **direction:** one (closer to one is better)
- **min_n:** 30 (config/kpi_targets.yaml, owner CFO (name); below this the value is stored but flagged not_measurable)

## 1 Purchase

### Purchase discount vs net launch RRP

- **id:** `KPI_PUR_DISCOUNT_VS_RRP`
- **page:** 1 Purchase
- **owner:** Head of Procurement (name)
- **definition:** One minus the paid unit price net of price protection credits over the net launch RRP of the variant (public catalogue RRP without VAT), summed over serials received in the trailing 12 months.
- **formula:** `1 - sum(device_ledger.purchase_price - price_protection_credit_eur) / sum(device_ledger.rrp_net_eur), received_at in trailing 12 months`
- **source tables:** `silver.device_ledger`
- **unit:** ratio
- **direction:** up (higher is better)
- **min_n:** 30 (config/kpi_targets.yaml, owner CFO (name); below this the value is stored but flagged not_measurable)

### Price protection captured

- **id:** `KPI_PUR_PRICE_PROTECTION_CAPTURE`
- **page:** 1 Purchase
- **owner:** Head of Procurement (name)
- **definition:** Credited price protection value over credited plus missed value on serials received in the trailing 12 months. A serial is missed when a price drop fell inside its protection window and no credit note arrived before the claim window closed; open claims are outside the denominator.
- **formula:** `sum(price_protection_credit_eur where status = claimed) / (that + sum(price_protection_claimable_eur where status = missed)), received_at in trailing 12 months`
- **source tables:** `silver.device_ledger`
- **unit:** ratio
- **direction:** up (higher is better)
- **min_n:** 30 (config/kpi_targets.yaml, owner CFO (name); below this the value is stored but flagged not_measurable)

## 3 Residual estimate

### Fleet estimate vs public anchor at lease end

- **id:** `KPI_RES_ESTIMATE_VS_ANCHOR`
- **page:** 3 Residual estimate
- **owner:** Head of Recommerce (name)
- **definition:** Sum of the fleet model's residual value estimate at lease end over the sum of the public-anchor curve value (marketplace asks, an upper bound) for the same serials, rented serials with an anchor only. - **formula:** `sum(device_ledger.estimate_rv_lease_end) / sum(device_ledger.anchor_rv_lease_end), lifecycle_status = rented and anchor not null`
- **source tables:** `silver.device_ledger`
- **unit:** ratio
- **direction:** one (closer to one is better)
- **min_n:** 30 (config/kpi_targets.yaml, owner CFO (name); below this the value is stored but flagged not_measurable)
